# Instructor 1.2 – Your workspace and the shared reference data

**Time:** 50 minutes · **Previous:** [Instructor 1.1](1.1-prepare.md) · **Next:** [Instructor 1.3](1.3-bridge.md)

Do this **the day before** the class, from your own clone with your own `.env`.

## 1. Your workspace

Do [Solo 1.2](../solo/1.2-fabric-workspace.md), for example with `FABRIC_WORKSPACE_NAME=rail-instructor`. This workspace
holds the reference Lakehouse and your demo pipeline. Include the raw tables and mappings.

If you skipped the Key Vault in Instructor 1.1, create it now: [Solo 1.1 §8](../solo/1.1-prerequisites.md#8-shared-key-vault-for-credentials-needed-from-solo-13).

## 2. Reference data

Do [Solo 1.3](../solo/1.3-reference-data.md), **Option A2** (the notebook), into **your** `RailLakehouse`.

## 3. Share the Lakehouse with the students

Students read your reference data through a OneLake shortcut ([Student 1.3](../student/1.3-reference-data.md)), so they
don't need an NROD login.

1. Open `RailLakehouse` → **Share**.
2. Add the student security group.
3. Tick **Read all OneLake data** → **Grant**.

*Check this in your tenant with one test student before the class.* Their shortcut must reach
`rail-instructor` → `RailLakehouse` → `Tables/locations`. Put that location in the handout (Instructor 1.5).

## Checkpoint

- [ ] Solo 1.2 and Solo 1.3 checkpoints pass in your workspace
- [ ] A test student can create the shortcut to your `locations` table (Student 1.3)
