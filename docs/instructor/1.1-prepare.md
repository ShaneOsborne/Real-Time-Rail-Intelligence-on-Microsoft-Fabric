# Instructor 1.1 – Prepare: accounts, tenant settings, capacity and Foundry

**Time:** 60 minutes, plus any account approval wait · **Previous:** [Instructor path](README.md) · **Next:** [Instructor 1.2](1.2-workspace-and-reference-data.md)

Start about **two weeks before** the class: some approvals take days.

**Do [Solo 1.1](../solo/1.1-prerequisites.md) first, then these extra steps.** Solo 1.1 gets your own NROD and RDM accounts,
Azure subscription, Fabric access, tools and the shared Key Vault. Only you need NROD, RDM and Azure: one NROD account and
one RDM subscription feed the whole class through the relay.

## 1. Accounts and subscriptions

| Task | Where | Notes |

| Register for NROD and subscribe to the feeds, including *All Reference Data* | [Solo 1.1 §1](../solo/1.1-prerequisites.md#1-network-rail-open-data-nrod) | Approval can take days |
| Subscribe to RDM *NWR Train Movements* (and *Darwin Push Port* if you'll demo Solo 1.5) | [Solo 1.1 §2](../solo/1.1-prerequisites.md#2-rail-data-marketplace-rdm) | One subscription feeds the whole class via the relay |

## 2. Student laptops and admin rights

Students need `az`, Python, Git, Node.js and Functions Core Tools. Docker and Power BI Desktop are optional (web routes
exist). Several installs need **admin rights or `sudo`**. Send the [Solo 1.1 §6](../solo/1.1-prerequisites.md#6-tools-on-your-machine)
list with the joining instructions, ask IT to pre-install on managed laptops, or provide lab VMs (Azure Cloud Shell covers
the `az` scripts).

## 3. Tenant settings for the student security group

Create a security group that contains every student. A Fabric admin then enables these settings for that group (as well as
for you), in *Admin portal → Tenant settings*. The full list and checks are in
[Solo 1.1 §4](../solo/1.1-prerequisites.md#4-microsoft-fabric).

* **Users can create Fabric items** (Real-Time Intelligence: Eventhouse, Eventstream, Activator).
* **Fabric data agent** settings (Copilot and Azure OpenAI-powered features), plus **cross-geo processing** and
  **cross-geo storage** for AI if your capacity region needs them.
* **Fabric Apps (preview)**, for Lab 2.8. Allow a few minutes to propagate.
* **Users can create ontology (preview) items**, only if the class does the optional Lab 2.5.

**Check Fabric Apps works in your capacity's region.** In a workspace on the class capacity: **+ New item → App (preview)**.
If it isn't listed, plan the [Lab 2.8 workaround](../build/2.8-rayfin-app.md#if-app-preview-isnt-available-in-your-region),
run Lab 2.8 as a demo, or drop it. Tell the students which (it's in their Lab 2.8 note).

## 4. Size and buy the Fabric capacity

Plan about **1.5–2 CU per student** (10 students ≈ F16–F32), as an estimate. The Foundry tool (Lab 2.6) needs a **paid** F2+.
See [Capacity planning – classrooms and shared capacities](../capacity-planning.md#classrooms-and-shared-capacities) and the
[classroom sizing notes in Instructor 1.4](1.4-shared-event-hub.md#classroom-sizing-fabric-capacity).

If students will create their own workspaces (Student 1.2), they need permission to assign workspaces to the capacity:
*Capacity settings → Contributor permissions*. Otherwise you create the workspaces for them in Instructor 1.5.

## 5. Shared Foundry project and roles

The class uses **one** shared Foundry project with a **gpt-5.4 / gpt-5.5** deployment (background mode).

1. **Check the model region first.** On [model availability](https://model-availability.azurewebsites.net/), find a region
   that offers gpt-5.4 or gpt-5.5 (for example, not UK West when tested). Create the Foundry resource and project there – a
   project can't change region later. Details: [Solo 1.1 §5](../solo/1.1-prerequisites.md#5-azure-ai-foundry-lab-26).
2. Deploy the model: [Lab 2.6, step 1](../build/2.6-foundry-agent.md#1-deploy-the-recommended-model-once-per-project).
3. Decide who adds the **Fabric IQ (OneLake Catalog)** tool to each student's agent. Every student needs **Foundry User**.
   Adding the Fabric IQ tool creates a project connection and needs **Foundry Project Manager**. Either give students that
   role, or add the tool for each student's agent yourself. You grant the roles in
   [Instructor 1.5](1.5-student-workspaces-and-handout.md#3-foundry-access-for-students).
