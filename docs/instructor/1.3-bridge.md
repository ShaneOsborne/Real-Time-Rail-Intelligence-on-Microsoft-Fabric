# Instructor 1.3 – The bridge

**Time:** 70 minutes · **Previous:** [Instructor 1.2](1.2-workspace-and-reference-data.md) · **Next:** [Instructor 1.4](1.4-shared-event-hub.md)

You run **one** NROD bridge for the whole class. Test it locally first, then deploy it to Azure. Instructor 1.4 then points
it at the shared Event Hub.

1. **Test locally.** Do [Solo 1.6](../solo/1.6-bridge-local.md), **Option A steps 1–6** (A1 local checks, then A2 to send to
   your own `RailEventstreamNrod`). The local Event Hub mode is optional and comes later, in
   [Instructor 1.4](1.4-shared-event-hub.md#optional-local-event-hub-mode).
2. **Stop the local bridge** (Ctrl+C). NROD allows one connection per account: the local and Azure bridges would keep kicking
   each other off.
3. **Deploy to Azure.** Do [Solo 1.7](../solo/1.7-bridge-azure.md). If your subscription blocks public access to Key Vault,
   use `SECRETS_SOURCE=inline` ([why](../solo/1.7-bridge-azure.md#if-your-subscription-blocks-public-access-to-key-vault)) –
   and remember it for Instructor 1.4, which needs the same setting.

*Optional:* [Solo 1.4](../solo/1.4-rdm-kafka-eventstream.md) (RDM Kafka source) and [Solo 1.5](../solo/1.5-darwin-push-port.md)
(Darwin) in your own workspace, as a demo. The class gets RDM through the relay in Instructor 1.4, so stop your Apache Kafka
source before then if it uses the same RDM consumer group.
