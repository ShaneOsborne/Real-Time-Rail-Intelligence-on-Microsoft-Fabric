# Student 1.3 – Reference data: shortcut to the instructor's Lakehouse

**Time:** 10 minutes · **Previous:** [Student 1.2](1.2-fabric-workspace.md) · **Next:** [Student 1.4](1.4-connect-to-the-class-feed.md)

## Objectives

Fill the KQL **`Locations`** table, which maps STANOX, TIPLOC, CRS and NLC codes to a name, latitude and longitude, so live
movements can be enriched. You don't have an NROD login, so you read the reference data your instructor loaded and shared.

## Steps

1. Check the `Locations` table exists in `RailKQL` (Student 1.2 created it): `Locations | count`.
2. In `RailKQL`: **+ New** → **OneLake shortcut** → *Microsoft OneLake* → select the **instructor's** `RailLakehouse` (from the
   handout, for example in workspace `rail-instructor`) → *Tables* → `locations` → **Create**. The shortcut must be called
   `locations`; rename it if Fabric adds a suffix.
3. Run `fabric/kql/05_reference_from_shortcut.kql` in a KQL queryset on `RailKQL`.

If the instructor's Lakehouse isn't listed, you haven't been given **Read all OneLake data** on it yet. Ask the instructor.

## Checkpoint

```kusto
Locations | summarize rows = count(), with_coords = countif(isnotnull(lat))
Locations | where crs in ("KGX", "LDS", "EDB", "MAN")
```

You should see tens of thousands of rows, and a few thousand with coordinates (stations only).

## Troubleshooting

| Symptom | Fix |
|---|---|
| The instructor's `RailLakehouse` isn't listed | You haven't been given **Read all OneLake data** on it yet. Ask the instructor |
| Few or no coordinates | The source data (NaPTAN) covers passenger stations only. Junctions and yards have no lat/lon. That's expected |
