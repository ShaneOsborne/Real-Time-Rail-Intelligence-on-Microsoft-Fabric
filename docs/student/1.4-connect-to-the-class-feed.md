# Student 1.4 – Connect to the class feed

**Time:** 15 minutes · **Previous:** [Student 1.3](1.3-reference-data.md) · **Next:** [Lab 2.1](../build/2.1-kql-transformations.md), or the optional [Student 1.5](1.5-darwin-class-feed.md) first

## Objectives

Your instructor runs one connection to Network Rail and the Rail Data Marketplace, and sends the data to a shared
**Azure Event Hubs** namespace. Here you add an **Azure Event Hubs** source to each of your two Eventstreams, so the live data
lands in your own Eventhouse tables `RawFeed` and `RdmTrustRaw`.

You need from the handout: the **namespace name** and **your own** consumer group, for example `student07`.

Your workspace signs in to the Event Hub with its own **workspace identity**, so there's no key to type. Do this first,
before S1:

1. Open your workspace → **Workspace settings** → **Workspace identity** → enable it. You need the **Admin** role on the
   workspace. If you can't enable it, ask your instructor.
2. Copy the **ID** shown on that page (not the **App ID**) and send it to the instructor, with your workspace name.
3. Wait until the instructor confirms they've given your workspace read access to the hub.

> **Handout gives you a key instead?** Some classes use key sign-in (`EVENTHUB_AUTH=key`, where the tenant allows it).
> Then skip steps 1–3, and in S1 choose **feature level Basic**, **Authentication kind**: **Shared Access Key**,
> **Shared Access Key Name** `students-listen` and the key from the handout.

> **Two settings that are easy to get wrong**
>
> * **Feature level: Extended features.** Workspace identity is only offered at this level (the source then shows as
>   **Azure EventHub Extended**). *Basic* offers only Shared Access Key. Don't associate a schema from the schema
>   registry: the parsing in Lab 2.1 doesn't need one.
> * **One connection per event hub.** A connection stores the namespace **and** the event hub. A connection made for
>   `nrod-feed` always reads `nrod-feed`, even when you add it to another Eventstream. Name each one after its hub.

> **Your own consumer group only.** Never `$Default` and never a classmate's: the events are split between everyone reading
> the same group.

## S1. NROD feed → `RawFeed`

1. Open **RailEventstreamNrod** → **Edit** → **Add source** → **Connect data sources** → search **Azure Event Hubs** → **Connect**.
2. **Choose feature level**: **Extended features** (that's where **Workspace identity** is offered). Select **New connection**:
   * **Event Hub namespace**: the namespace name from the instructor. **Event Hub**: `nrod-feed`.
   * **Connection name**: `rail-nrod-feed`.
   * **Authentication kind**: **Workspace identity** → **Connect**. There's no key to type.
3. **Consumer group**: **your own** (for example `student07`). Never `$Default` and never a classmate's.
4. **Data format**: **JSON** → **Next** → **Add**.
5. **Add destination** → **Eventhouse** → **Direct ingestion** → `RailEventhouse` / **`RailKQL`** (not the default database
   named after the Eventhouse) → **Save** → **Publish**.
6. In the Eventstream's **Live view**, select **Configure** on the Eventhouse node. The **Get data** wizard reads a sample of
   the incoming events. Choose the **existing** table **`RawFeed`** (not *New table*), format **JSON**, and the **existing
   mapping** **`RawFeedMapping`** → **Finish**. Don't let the wizard create a table: Lab 2.1 needs the one `payload` column.

   *Direct ingestion* works. If you want to be able to rewind the destination too, choose *Event processing before ingestion*:
   that destination supports pause/resume with **Custom time**, whereas *Direct ingestion* doesn't
   ([Pause and resume data streams](https://learn.microsoft.com/en-us/fabric/real-time-intelligence/event-streams/pause-resume-data-streams)).

## S2. RDM feed → `RdmTrustRaw`

Repeat S1 in **RailEventstreamRdm**, with **feature level Extended features** and a **new connection** for **Event Hub** `rdm-trust`
(name it `rail-rdm-trust`). Don't pick `rail-nrod-feed`: it would bring the NROD feed into this Eventstream. Use **the same
consumer group name**, data format **JSON**, and destination table **`RdmTrustRaw`** with mapping **`RdmTrustRawMapping`**
(*Direct ingestion*, then **Configure** in Live view). You don't add an Apache Kafka source.

**Check before you publish:** look at the source's **Data preview**. If it shows columns `source` = `nrod`, `topic` =
`RTPPM_ALL` and `feed` = `rtppm`, the source is reading `nrod-feed`, not `rdm-trust`: change its connection.

> **Darwin is optional.** Darwin forecasts and platforms come from a third hub, `rdm-darwin`, and only if your instructor
> runs it: your handout then has an *Optional Darwin feed (Student 1.5)* row. Don't add it to this Eventstream. It has its
> own one in [Student 1.5](1.5-darwin-class-feed.md).

## Checkpoint

Give it a few minutes, then run these in a KQL queryset on `RailKQL`:

```kusto
RawFeed | summarize events = count(), last_received = max(received_utc), last_ingested = max(ingestion_time()) by feed
RdmTrustRaw | summarize n = count() by t = bin(ingestion_time(), 1m) | order by t desc | take 10
TrustMovements | summarize n = count(), ['last'] = max(event_time) by source
```

`RawFeed` and `RdmTrustRaw` should have rows. `TrustMovements` fills once the update policies are in place (you created them
in Student 1.2; Lab 2.1 adds the rest).

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Eventstream source errors mentioning `ReceiverDisconnected` or "a new receiver with higher epoch" | Two Eventstreams (or an Eventstream and another reader) use the **same consumer group** and keep taking the partitions from each other | Give every Eventstream its own consumer group. Check nobody else typed `$Default` or a classmate's group |
| Source shows an authorisation error (`Unauthorized`, `401`, "put token failed") | Wrong key name or key, a hub-level key used with the wrong hub, or the key was rotated | Use key name `students-listen` with the **namespace-level** key. Ask the instructor for the current key |
| Source won't connect with **Workspace identity** (an authorisation or "unauthorized" error) | Workspace identity isn't enabled on your workspace, or the instructor hasn't given it read access yet (it can take a few minutes) | Check **Workspace settings** → **Workspace identity** is enabled. Send the **ID** from that page (not the App ID) to the instructor, wait for confirmation, then try again |
| **Failed to publish changes** … *Required property 'type' not found in JSON* (a path such as `schema.columns[6].fields…`) | With **Extended features**, Eventstream works out a schema from the messages. It can't type a field that's only ever empty (null), or one that's an object in one message and a list in another, as some NROD RTPPM fields are. The class bridge and relays now fix both, but messages sent before the instructor updated them are still in the hub | Tell the instructor (they redeploy with `deploy-bridge`, see Instructor 1.4 Troubleshooting). Wait about an hour after that, then delete the source → **Publish**, and add it again with **Starting position** **Latest** |
| Data preview in **RailEventstreamRdm** shows `source` = `nrod`, `topic` = `RTPPM_ALL` | The source uses the `nrod-feed` connection. A connection is tied to one event hub | Edit the source and pick (or create) a connection for `rdm-trust`. If NROD rows already reached `RdmTrustRaw`, run `.clear table RdmTrustRaw data` |
| Source can't connect at all | Namespace isn't publicly reachable (firewall, private endpoint) | Ask the instructor: the namespace needs public access on, or a Fabric managed private endpoint |
| No existing `RawFeed` / `RdmTrustRaw` in the table list, or no "existing mapping" option | The tables and mappings weren't created first | Do "Create the raw tables and mappings now" in [Student 1.2](1.2-fabric-workspace.md#create-the-raw-tables-and-mappings-now), then re-open **Configure** on the destination |
