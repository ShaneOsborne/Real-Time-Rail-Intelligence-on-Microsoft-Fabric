# Rayfin app starter – map + "chat with the network" (Lab 11)

This folder is **not** a complete app. Rayfin projects are generated by the Rayfin CLI, so you scaffold a project
**next to this repo** (not inside it) and copy the overlay files from `rayfin-starter/` into it.

> Status (Oct 2026, Rayfin 1.36.2): Fabric Apps is **preview**. **New Kusto connectors can't be added** in 1.36.2
> (`connector add --type kusto` → *not available in this release*), and functions have **no Kusto token audience**. So the
> map reads a **DirectQuery semantic model** over `RailKQL` ([Lab 10b](../docs/labs/10b-live-semantic-model.md)) through the
> `fabric-semanticmodel` connector (preview), and the chat calls Foundry through a function.

## Steps

The steps live in **one place only**: [Lab 11 – Option A](../docs/labs/11-rayfin-app.md#option-a--cli-plus-overlay-code).
Follow that, including its PowerShell notes and troubleshooting. In short, with the Rayfin 1.36 default template:
scaffold `rail-app` → `npm run pack:add -- functions` and `-- connectors` → `npx rayfin connector add --type
fabric-semanticmodel … --name railmap` (+ its printed `npm install`) → copy `rayfin-starter/packages/*` onto `packages/` → set
the two values, check the client import, swap `EmptyStatePreview` for `RailApp` → `npx rayfin dev functions apply` (until the
types list `askRailAgent`) → `npm run validate:functions`, `typecheck`, `build` → `npm run rayfin:up`.

`rayfin-starter/` mirrors the default template's layout (`packages/frontend`, `packages/functions`), so the files copy straight across.

**Optional – [Lab 11b](../docs/labs/11b-azure-maps.md):** `rayfin-maps-addon/` is copied on top of that to swap the simple SVG map for an
Azure Maps map (grayscale/road/night/satellite styles, OS Open Zoomstack railway lines, train pop-ups). It needs
`npm install -w @rayfin-app/frontend azure-maps-control`, the `getMapAuth` function (already in `function_app.ts`) and the
`AZURE_MAPS_TOKEN` secret. Without the secret the app keeps the simple map. `tools/build_gb_rail.py` builds
`rayfin-maps-addon/packages/frontend/public/data/gb-rail.geojson` from OS Open Zoomstack.

## What each overlay file does

| File | Purpose |
|---|---|
| `packages/frontend/src/services/railClient.ts` | Adapter: gets the template's authenticated client (`getRayfinClient()`) and returns its typed `functions` and the `railmap` connector |
| `packages/frontend/src/features/network/loadSnapshot.ts` | Fixed DAX query to the `railmap` semantic model connector (`TrainPositions`), mapped to train positions |
| `packages/frontend/src/features/network/NetworkMap.tsx` | Dependency-free SVG map of GB, coloured by delay, refreshes every 30 s |
| `packages/frontend/src/features/chat/ChatPanel.tsx` | *Ask the network* chat: suggested questions, message bubbles, typing indicator, Markdown tables in answers |
| `packages/frontend/src/RailApp.tsx` | Rendered from `App.tsx` in place of the welcome page; puts the map into `AppShell` |
| `packages/frontend/src/AppShell.tsx` | Branded layout: header with live status, KPI strip, map + chat grid, attribution footer |
| `packages/frontend/src/theme/brand.ts`, `theme/rail.css` | Brand name, strapline and colours; scoped styles (`.rp`) |
| `packages/frontend/src/features/network/useSnapshot.ts` | One shared 30-second poller for the train snapshot (map and KPIs share one query) |
| `packages/frontend/src/features/network/KpiStrip.tsx` | Active trains, % on time, late, very late, operators |
| `packages/functions/src/function_app.ts` | `askRailAgent` (`ctx.Tokens.AzureAI` → Foundry agent from Lab 10) |

## Unverified / to check

* Confirmed with the 1.36 default template: the client module is `lib/rayfin-client.ts`, and functions need
  `npx rayfin dev functions apply` (installs Core Tools) before type generation works. Not yet confirmed end to end: the
  deployed map and chat calls.
* The map assumes `npm run pack:add -- connectors` + `connector add --name railmap` expose `client.connectors.railmap` on the
  template's `getRayfinClient()` client (per the template's connectors skill). Rayfin connectors are preview.
* `askRailAgent` uses `ctx.Tokens.AzureAI`. Deployed, that's the app identity (the App item's owner); the Foundry Fabric data
  agent tool needs a user identity, so check the deployed chat as well as the local one.
* The Foundry REST call in `askRailAgent` (`POST {project}/openai/v1/responses` with `agent_reference`) is marked
  `TODO(verify)`. Check it against https://ai.azure.com/api-reference/responses/ for your API version.
* If functions aren't available in your tenant, the map still works; use the Foundry playground for chat.
