# Rayfin app starter – map + "chat with the network" (Lab 11)

This folder is **not** a complete app. Rayfin projects are generated by the Rayfin CLI, so you scaffold a project
**next to this repo** (not inside it) and copy the overlay files from `rayfin-starter/` into it. See
[Lab 11](../docs/labs/11-rayfin-app.md) for the full steps, where to find each value, and troubleshooting.

> Status (Oct 2026, Rayfin 1.36.2): Fabric Apps is **preview**. **New Kusto connectors can't be added** in 1.36.2
> (`connector add --type kusto` → *not available in this release*), so this starter reads the Eventhouse through a
> **function** with an `AudienceType.Kusto` token instead. Functions aren't available in every tenant/region.

## Steps (Rayfin 1.36 default template)

The default template is a **Universal App** npm workspace (`packages/frontend`, plus `packages/functions` after the functions
pack). `rayfin-starter/` mirrors that layout, so you copy `packages/` onto `packages/`.

```bash
# From the folder ABOVE this repo
npm create @microsoft/rayfin@latest -- rail-app --workspace rail-fabric-rti   # workspace NAME; choose "✨ Use default template"
cd rail-app
npx rayfin login
npm run pack:add -- functions          # NOT `npx rayfin functions init`

LAB_REPO=../Real-Time-Rail-Intelligence-on-Microsoft-Fabric      # path to your clone, from inside rail-app
cp -r "$LAB_REPO"/app/rayfin-starter/packages/* packages/
#   PowerShell: robocopy "$env:LAB_REPO\app\rayfin-starter\packages" packages /E   (Copy-Item won't merge existing folders)
#  1. packages/functions/src/function_app.ts: set KUSTO_QUERY_URI, KQL_DATABASE, FOUNDRY_PROJECT_ENDPOINT, FOUNDRY_AGENT_NAME
#  2. packages/frontend/src/services/railClient.ts: check the import ('../lib/rayfin-client' in the 1.36 template)
grep -rl "export.*getRayfinClient" packages/frontend/src
#  3. packages/frontend/src/App.tsx: replace EmptyStatePreview (import and element) with RailApp

npm run dev                            # generates function types; Ctrl+C when ready
npm run validate:functions && npm run typecheck && npm run build
npm run rayfin:up
```

## What each overlay file does

| File | Purpose |
|---|---|
| `packages/frontend/src/services/railClient.ts` | Adapter: gets the template's authenticated client (`getRayfinClient()`) and returns its typed `functions` |
| `packages/frontend/src/features/network/loadSnapshot.ts` | Calls `getNetworkSnapshot` and maps rows to train positions |
| `packages/frontend/src/features/network/NetworkMap.tsx` | Dependency-free SVG map of GB, coloured by delay, refreshes every 30 s |
| `packages/frontend/src/features/chat/ChatPanel.tsx` | Chat UI calling `askRailAgent` |
| `packages/frontend/src/RailApp.tsx` | Two-panel layout, rendered from `App.tsx` in place of the welcome page |
| `packages/functions/src/function_app.ts` | `getNetworkSnapshot` (`AudienceType.Kusto` → KQL REST `/v1/rest/query`, fixed query) and `askRailAgent` (`AudienceType.AzureAI` → Foundry agent from Lab 10) |

## Unverified / to check

* Not yet tested end to end in the Universal App template: the `getRayfinClient` module path (hence the one-line edit), and
  type generation through `npm run dev`.
* `getNetworkSnapshot` relies on the Rayfin SDK supplying a token for `AudienceType.Kusto` that the Fabric KQL query endpoint
  accepts. Deployed functions use the **app identity**, so grant the App item Viewer on `RailKQL`. Test with `npm run dev` before a class.
* `askRailAgent`: the Foundry Fabric data agent tool supports user identity only, so it may fail under the app identity when deployed.
* The Foundry REST call in `askRailAgent` (`POST {project}/openai/v1/responses` with `agent_reference`) is marked
  `TODO(verify)`. Check it against https://ai.azure.com/api-reference/responses/ for your API version.
* If functions aren't available in your tenant, use the Lab 08 dashboard for the map and the Foundry playground for chat.
